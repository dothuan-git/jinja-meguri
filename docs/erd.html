Reading the model

The calendar lives in two tables. events defines a festival once (lore, plus time_prose like “2nd Sunday of May”). event_occurrences holds the concrete dated rows you upload each January — the only table the calendar queries, via date-range overlap.

Lore has a fallback. Regional deity lore on shrine_deities.lore takes priority; deities.canonical_lore is the Kojiki-level backup. Read-time COALESCE applies the “prefer regional” rule.

Filters are facets, not prose. shrine_categories (“strong for”), shrine_types (all ranks as rows), region and prefecture are all joinable — the listing page filters on rows, never on text.
